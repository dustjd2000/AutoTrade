# LLM 종목 추천 프롬프트 개선 설계

## 배경

`AutoTrade Env/llm_prompt_template.py`(참고용 레퍼런스, 이 저장소 밖)를 참고해
`src/llm/recommender.py`의 LLM 종목 추천 프롬프트 품질을 개선한다.

레퍼런스 템플릿은 업종 분산, 해외지수·야간선물, 실제 뉴스/공시까지 프롬프트에 넣지만,
PRD 10절에 뉴스/공시 소스가 아직 미확정이라고 명시돼 있고 해외지수·야간선물은 PRD 범위 밖이라
새 데이터 수집 연동이 필요한 별도 작업이다. 이번 개선은 **현재 수집 중인 데이터
(등락률·거래량·시가갭·뉴스헤드라인)만으로 프롬프트 품질을 올리는 것**으로 범위를 좁혔다.
데이터 확장(업종·해외지수·실뉴스 연동)은 이번 범위에서 제외하고 필요 시 별도 설계로 진행한다.

## 범위

- 변경 파일: `src/llm/recommender.py` 만.
- 출력 스키마(`RECOMMENDATION_SCHEMA`)와 `StockRecommendation` 데이터클래스는 그대로 둔다
  (ticker/name/reason 3개 필드 유지) — 이메일 템플릿·다운스트림 코드 영향 없음.
- `DailyStockData`, `DataCollector`, `NewsClient` 등 데이터 수집 계층은 건드리지 않는다.

## 변경 내용

### 1. `SYSTEM_PROMPT` 재작성

현재는 역할 설명 한 문단뿐이다. 템플릿의 구조(절대 규칙 → 판단 기준 → 근거 작성 지침)를
가져오되, 실제로 제공되는 필드에 맞게 조정한다.

- **절대 규칙**: 제공된 종목만 선택, 학습 데이터(모델의 사전 지식) 의존 금지, 중복 선택 금지,
  근거가 확실한 종목이 3개 미만이면 억지로 채우지 않고 최소 1개~그 수만큼만 추천.
- **판단 기준** (제공 데이터 범위 내 우선순위): 시가갭 방향성/크기 → 등락률 → 거래량(절대 급증
  여부가 아니라 함께 제공된 다른 종목과의 상대적 규모로만 참고 — 20일 평균 거래량 데이터가 없어
  절대적 판단은 불가능함을 명시) → 뉴스/공시 헤드라인의 구체성.
- **근거 작성 지침**: `reason`은 제공된 데이터의 구체적 수치를 인용해야 하며, "긍정적 모멘텀"류의
  모호한 표현을 금지.
- 템플릿에 있던 업종 분산·해외지수·야간선물·거래량 평균배수 언급은 대응하는 데이터가 없으므로
  제외.
- 출력 JSON 형식 설명은 프롬프트에 넣지 않는다 — 이미 Anthropic 구조화 출력
  (`output_config.format.json_schema`)으로 API가 형식을 강제하므로 템플릿처럼 프롬프트에서
  형식을 다시 설명할 필요가 없다 (기존 방식이 템플릿보다 안전함).

### 2. `build_user_prompt()` 마지막 지시문 수정

```python
# 변경 전
"위 데이터를 참고해 급등 예상 종목 3개를 JSON 배열로 추천하세요."
# 변경 후
"위 데이터를 참고해 급등 예상 종목을 최대 3개까지, 근거가 확실한 만큼만 JSON 배열로 추천하세요."
```

`parse_recommendations`는 빈 배열을 여전히 예외로 처리한다(변경 없음) — "확신이 서는 종목이
전혀 없으면 매수 스킵"이라는 기존 동작과 자연스럽게 맞물린다. 따라서 프롬프트는 "최소 1개"까지만
허용하고 0개를 명시적으로 허용하지 않는다.

### 3. `temperature=0.3` 명시

`recommend()`의 `messages.create()` 호출에 `temperature=0.3`을 추가한다. 현재는 파라미터가
없어 API 기본값(높은 온도)을 쓰는데, 매수 판단이라는 용도상 매번 결과가 크게 흔들리는 것보다
일관된 판단이 우선이라는 템플릿의 근거를 그대로 채택한다.

### 4. 버전 표기

`PROMPT_TEMPLATE_VERSION`을 `"v1"` → `"v2"`로 올린다. 이 값은 로그(`LLM recommended %d
stock(s) (prompt_version=%s)`)에 남아 추천 근거를 프롬프트 버전별로 추적하는 용도로 이미
쓰이고 있다.

## 하위 호환성 / 다운스트림 영향

- 추천 개수가 3개 미만으로 나올 수 있다는 점은 이미 다운스트림에서 처리된다:
  `LLMMomentumStrategy.build_buy_plans`(종목당 예수금의 1/6 고정, 모자란 몫은 현금 유지)와
  `templates.recommendation_email`(3개 미만일 때 안내 문구)이 이미 이 상황을 지원한다.
  이번 변경은 그 경로가 실제로 더 자주 쓰이게 만들 뿐, 새 처리 로직이 필요하지 않다.
- 출력 스키마가 그대로이므로 `parse_recommendations`, 이메일 템플릿, 매수 실행 로직은
  변경이 필요 없다.

## 테스트

- 기존 `tests/test_llm/test_recommender.py`의 `test_build_user_prompt_includes_all_stock_data`는
  문자열 부분 일치(`in`)만 확인하므로 문구 변경과 무관하게 통과해야 한다.
- `SYSTEM_PROMPT`나 마지막 지시문의 정확한 문구를 assert하는 테스트는 없다 — 확인 결과 없음.
- 새로 추가할 테스트: `recommend()` 호출 시 `messages.create`에 `temperature=0.3`이 전달되는지
  확인하는 테스트 1개 (`_fake_recommender`의 `create` mock이 kwargs를 캡처하도록 확장).
- 나머지는 기존 테스트 스위트 재실행으로 회귀 여부만 확인한다 (프롬프트 문구는 LLM 호출 없이는
  실제 추천 품질을 검증할 수 없음 — 이번 변경의 효과는 실사용/모의투자 관찰로 확인해야 한다).
