# 2호 전략 규칙 자동 검증·적용 설계

- 작성일: 2026-10-29
- 대상: 2호 전략(지수 ETF 국면 추종, PRD 5.5-C)
- 상태: 설계 승인, 구현 전

## 1. 목적

사용자 목표는 "매월 순수익 5%를 향해 프로그램이 스스로 개선하는 것"이다. 실전 기록(하루 1건)으로는
개선 여부를 가릴 표본이 모자라므로, **1분봉 과거 데이터로 규칙 후보를 매주 검증하고, 엄격한 조건을
모두 만족하면 `.env` 설정을 자동으로 바꾼다.**

월 5%는 보장하는 목표가 아니다. 이 기능은 근거 있는 방향으로만 규칙을 옮기는 장치다.

### 계기 (2026-10-29 세션)

같은 1분봉(069500/114800, 2025-10-01~2026-10-28, 259거래일, 09:10 진입, 손절 2%, 15:15 청산,
수수료 0.015%×2, 슬리피지 체결당 호가 반칸 2.5원)에서 규칙에 따라 성과가 크게 갈렸다.

| 규칙 | 일 평균 (슬리피지 포함) | 누적 |
|---|---|---|
| 문턱 ±0.2%, 뒤집기 없음 | +0.090% | +15.7% |
| 문턱 ±0.2%, 뒤집기 있음 | -0.263% | -45.8% |
| 문턱 0, 뒤집기 없음 | -0.047% | -11.2% |
| 문턱 0, 뒤집기 있음 (2026-10-29 실전) | -0.321% | -76.8% |

규칙 선택이 성과를 좌우하므로, 이 비교를 사람이 손으로 하는 대신 매주 자동으로 돌린다.

## 2. 결정 사항 (사용자 확정)

1. **탐색 범위**: 이미 있는 손잡이만 돌린다. 새 규칙(트레일링, 신호 기간 등)은 넣지 않는다.
2. **채택 방식**: 조건을 모두 만족하면 사람 승인 없이 자동 적용한다.
3. **평가 주기와 조건**: 매주 금요일 평가, 엄격한 조건(4절).
4. **시작 규칙**: 지금 `.env` 규칙 그대로 시작한다. 첫 적용도 4주 연속 조건을 똑같이 거친다.
5. **실행 위치**: 엔진 안의 스케줄 작업. 키움은 앱키당 토큰을 하나만 유지하므로 별도 프로세스로 분봉을
   받으면 엔진 토큰이 무효화된다 (CLAUDE.md, PRD 10절 "토큰 무효화").

## 3. 후보 규칙

네 손잡이의 조합 160개다.

| 손잡이 | `.env` 키 | 후보 |
|---|---|---|
| 신호 문턱(%) | `ETF_SIGNAL_BAND_PERCENT` (신설) | 0, 0.1, 0.2, 0.3 |
| 방향 뒤집기 | `ETF_FLIP_ENABLED` (신설, 1/0) | 켬, 끔 |
| 결정 시각 | `RECOMMEND_TIME` | 09:05, 09:10, 09:30, 10:00 |
| 손절(%) | `STOP_LOSS_PERCENT` | 1, 1.5, 2, 2.5, 3 |

- 신호 문턱: 20일 신호의 절댓값이 문턱 미만이면 그날 쉰다. 0이면 매일 산다(현행).
- 방향 뒤집기: 오늘 KODEX 200 시가 대비 움직임이 신호와 반대로 `FLIP_PERCENT`(0.2%) 이상이면 반대쪽을 산다(현행).
- 결정 시각을 바꾸면 `BUY_TIME`은 결정 +3분으로 함께 쓴다 (`Settings.validate()`가 +3분 이상을 요구한다).
- 신설 두 키의 기본값은 지금 코드 동작과 같게 둔다: `ETF_SIGNAL_BAND_PERCENT=0`, `ETF_FLIP_ENABLED=1`.
  이 설정화는 동작을 바꾸지 않는다.
- 규칙이 설정에 없는 값(예: 손절 1.8%)이면, 현행 규칙도 그 값 그대로 평가한다. 후보 목록에 없어도 된다.

## 4. 평가와 적용 조건

### 4.1 평가 (매주 금요일 16:00)

1. 저장된 분봉 중 품질 기준(5.3)을 통과한 거래일을 쓴다.
2. **고르기 구간** = 최근 63거래일(약 3개월)을 뺀 앞 기간. **시험 구간** = 최근 63거래일.
3. 고르기 구간에서 160개 후보의 일 평균 순수익률을 계산해 1등을 고른다. 동점이면 현행 규칙에 가까운
   후보(바뀌는 손잡이 수가 적은 쪽)를 고른다.
4. 시험 구간에서 1등 후보와 현행 규칙의 일 평균 순수익률을 계산한다.
5. 결과를 `rule_evaluations`에 기록하고 메일로 보낸다.

일 평균은 **달력상 거래일 전체로 나눈다** — 쉬는 날은 0%로 센다. 문턱을 올려 거래일을 줄이는 후보가
남은 날의 평균만으로 유리해 보이지 않게 하려는 것이다.

### 4.2 적용 조건 (모두 만족)

1. **시험 구간 우위**: 1등 후보 − 현행 ≥ 0.05%p/일.
2. **절대 기준**: 1등 후보의 시험 구간 일 평균 > 0.
3. **일관성**: 이번 주를 포함해 최근 4번의 평가에서 같은 후보가 1등이고, 4번 모두 1·2를 만족했다.
   중간에 "판정 실패"나 "평가 안 함"이 있으면 연속이 끊긴다.
4. **휴지 기간**: 마지막 자동 적용 이후 4번 이상 평가가 지났다(약 4주).
5. **자동 적용 스위치**: `RULE_AUTO_APPLY_ENABLED=1`. 0이면 평가·기록·메일만 하고 적용하지 않는다.

1등 후보가 현행 규칙과 같으면 적용할 것이 없다 — "현행 유지"로 기록한다.

### 4.3 적용

1. 적용 직전 확인: 보유 종목이 없고, 새 값이 후보 범위 안이며, 새 값으로 만든 `Settings`가 `validate()`를
   통과한다. 하나라도 어긋나면 적용하지 않고 사유를 기록한다. 보유 종목 때문에 못 했으면 다음 평가로 미룬다.
2. `src/ui/env_store.save_env`로 바뀌는 키만 쓴다.
3. 엔진이 UI에 재시작을 요청한다. UI는 기존 `_restart_engine` 경로로 재시작하고, 재시작 시 설정 화면이
   `.env`를 다시 읽는다. 다시 읽지 않으면 다음 "설정 저장"이 옛 손절값으로 덮어쓴다.
4. 적용 메일을 보낸다: 무엇을, 왜(4주 평가 수치), 이전 값.

## 5. 구성 요소

### 5.1 분봉 수집

- `src/api/market_data.py`에 `get_minute_candles(ticker, since: date)`를 추가한다. ka10080 연속조회
  (`/api/dostk/chart`, `tic_scope="1"`, `upd_stkpc_tp="1"`, 응답 키 `stk_min_pole_chart_qry`)로 최신부터
  거꾸로 받다가 `since`보다 이전 날짜가 나오면 멈춘다. 호출 사이 0.4초 쉰다.
- `src/research/minute_store.py`: 종목별 JSON 파일(`data/minute/<ticker>.json`)에 `{날짜: [[HHMM, 종가], ...]}`
  꼴로 저장한다. 같은 날짜는 덮어써 중복을 없앤다. 파일 쓰기는 임시 파일 → `os.replace`로 원자적으로 한다.
- `DailyWorkflow.collect_minute_bars` (매일 15:45): 저장된 마지막 날짜 다음 날부터 오늘까지 받는다. 저장소가
  비었으면 키움이 주는 범위만큼 받는다(약 13개월, 수 분). 실행 큐를 타고 별도 스레드에서 돈다.

### 5.2 백테스트

- `src/research/backtest.py`: 분봉과 규칙 하나를 받아 거래일별 순수익률을 돌려주는 순수 함수.
  - 신호: 직전 20거래일 KODEX 200 장중(첫 봉 → 마지막 봉) 수익률 평균. 실전 `etf_regime.regime_signal`과
    같은 정의를 쓰되 분봉에서 계산한다.
  - 방향: 실전 `etf_regime.pick_etf`를 불러 정한다 — 문턱과 뒤집기 여부를 인자로 받도록 `pick_etf`를 넓힌다.
  - 진입: 결정 시각 이후 첫 봉 종가 + 반호가(2.5원). 청산: 순손익률이 −손절 이하가 된 첫 봉, 또는 15:15
    이후 첫 봉의 종가 − 반호가. 수수료는 `Settings.commission_ratio`로 양방향.
  - AI 매도 판단은 재현하지 않는다.
- `src/research/rule_search.py`: 후보 생성, 고르기·시험 구간 분리, 1등 선택, 4.2의 조건 1·2 판정.
  DB·메일을 모르는 순수 함수. 조건 3·4는 기록을 받아 판정하는 별도 함수로 둔다.

### 5.3 데이터 품질

- 하루 봉이 300개 미만인 날은 뺀다(반일장·수집 누락).
- 두 종목 모두 있는 날만 쓴다.
- 평가에 쓸 거래일이 20(신호) + 120 미만이면 평가하지 않고 "데이터 부족"으로 기록한다.

### 5.4 설정 (`config/settings.py`)

| 키 | 기본 | 설명 |
|---|---|---|
| `ETF_SIGNAL_BAND_PERCENT` | 0 | 20일 신호 문턱. `etf_regime.MIN_SIGNAL_PERCENT`를 대체 |
| `ETF_FLIP_ENABLED` | 1 | 방향 뒤집기 사용 여부 |
| `RULE_AUTO_APPLY_ENABLED` | 1 | 자동 적용 스위치 |

UI에는 노출하지 않는다.

### 5.5 기록 (`data/trades.db`, `rule_evaluations` 테이블)

평가일, 상태(평가함 / 데이터 부족 / 판정 실패), 현행 규칙, 1등 후보, 고르기·시험 구간 일 평균(둘 다),
조건 1·2 충족 여부, 적용 여부와 사유. 규칙은 네 손잡이를 JSON 문자열로 남긴다.

### 5.6 스케줄과 실행 큐

- `runtime`에 `MINUTE_COLLECT_TIME = 15:45`, `RULE_EVAL_TIME = 16:00`(금요일만)을 추가한다.
- `actions`에 `collect_minute_bars`, `evaluate_rules`를 스케줄 액션으로 추가한다. 주문 단계가 아니므로
  루프 밖 스레드에서 돈다. 휴장일에는 `runtime._submit`이 건너뛴다.
- 금요일이 휴장이면 그 주 평가는 없다(연속 4번은 "평가 기록 4건" 기준이라 휴장 주는 연속을 끊지 않는다).

### 5.7 메일

- 매주 평가 결과: 현행·1등 후보의 두 구간 성과, 조건별 충족 여부, 연속 횟수, 휴지 기간 남은 횟수.
- 적용한 주: 바꾼 값, 이전 값, 근거.
- 기존 `EmailNotifier`와 `notification/templates.py` 패턴을 따른다.

## 6. 실패 처리

어떤 실패도 매매를 막지 않고, 실패하면 "바꾸지 않음"으로 끝난다.

| 상황 | 처리 |
|---|---|
| 분봉 수집 실패 | 그날만 빠진다. 다음 수집이 마지막 저장일 다음 날부터 다시 받는다. 로그와 운영 알림 |
| 데이터 부족 | 평가하지 않고 사유를 기록·메일 |
| 평가 중 예외 | "판정 실패"로 기록, 적용 안 함 (연속이 끊긴다) |
| 보유 종목 있음 | 적용을 다음 평가로 미룸 |
| 범위·`validate()` 위반 | 적용 안 함, 사유 기록 |
| `.env` 쓰기 실패 | 적용 안 함, 사유 기록 |

## 7. 테스트

모두 API 없이 가짜 분봉으로 한다.

- `backtest`: 진입가, 손절, 15:15 청산, 비용, 문턱 쉼, 뒤집기를 작은 가짜 분봉으로 손계산과 대조.
- `rule_search`: 1등 고르기가 고르기 구간만 보는지(시험 구간 데이터가 새지 않는지), 동점 처리,
  쉬는 날 0% 포함 평균, 조건 1·2 경계.
- 연속·휴지 판정: 4번 연속, 중간 실패로 끊김, 휴지 기간 경계.
- `minute_store`: 추가, 같은 날짜 덮어쓰기, 마지막 저장일.
- `evaluate_rules`: 적용, 스위치 끔, 보유 중 연기, `.env` 쓰기 실패, `validate()` 실패.
- 설정: 신설 키 기본값이 지금 동작과 같은지, `pick_etf`가 문턱·뒤집기 인자를 반영하는지.
- 회귀(선택): 실제 분봉 파일이 있을 때만, "문턱 0.2% + 뒤집기 없음 + 09:10 + 손절 2%"가 +0.090%/일
  근처인지 확인한다.

## 8. 하지 않는 것

- AI 매도 판단 시뮬레이션
- 새 규칙 탐색(트레일링 스탑, 신호 기간, 투입 비율 등)
- UI 적용 버튼, UI 설정 노출
- 시작 규칙 자동 맞춤

## 9. 알려진 한계

- 평가는 손절과 15:15 청산만으로 한다. 실전에는 AI 매도 판단이 있어 성과가 다르다.
- 체결가를 분봉 종가로 가정한다. 슬리피지는 반호가로 고정한다.
- 고르기 구간이 짧다(처음에는 약 57거래일). 데이터가 쌓일수록 나아진다.
- 160개 중 1등을 고르는 과정 자체가 우연한 승자를 고를 위험이 있다. 시험 구간 비교와 4주 연속 조건이
  이를 줄이지만 없애지는 못한다.
