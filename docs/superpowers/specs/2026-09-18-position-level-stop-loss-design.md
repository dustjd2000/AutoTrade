# 종목별 손절과 익절 제거 — 설계

작성 2026-09-18. 관련: PRD 5.5-B "매도(청산) 조건", PRD 10절 2026-08-10·2026-09-09 결정.

## 배경

사용자 관찰: "하락은 방어가 되는데 이익일 때 매도를 안 한다."

로그(2026-09-09~09-18)로 확인한 결과 관찰은 정확하고, 원인은 익절 기능의 부재가 아니었다.

**보유 중 종목이 도달한 당일 최대 이익** — 익절선은 5%인데 근처도 가지 않는다.

```
062040 산일전기   +2.17%   ← 관측 최대
005380 현대차     +1.26%
278470 에이피알   +1.02%
000810 삼성화재   +0.97%
036570 NC         +0.49%
005940 / 009540   +0.35%
267270 / 278470   +0.14% 이하
```

**AI 매도 판단이 청산한 시점의 합산 순손익** — 6번 중 5번이 마이너스다.

| 날짜 | 시각 | 합산 |
|---|---|---|
| 09-11 | 09:20 | +0.27% |
| 09-14 | 11:20 | -2.45% |
| 09-15 | 12:57 | -1.85% |
| 09-16 | 10:32 | -0.46% |
| 09-17 | 09:20 | -0.26% |
| 09-18 | 10:29 | -0.19% |

즉 **이익이 커지기 전에 AI가 전량 정리해 버린다.** 매수 후 1~2시간 만에 끝나는 날이 많다.
익절선 5%는 도달할 기회 자체가 없고, 종목별로 바꿔도 발동하지 않는다.

세 가지가 맞물려 있다.

1. **이익 반납 감시가 과민하다.** 고점 +0.05%에서 1%p 내려간 것도 "고점 이익의 100% 반납"
   으로 AI를 호출한다. 이는 이익 반납이 아니라 매수가 근처의 출렁임이다.
2. **AI가 손절선을 판단 기준으로 쓴다.** 보유 유지 사유가 거의 전부 "손절선(-5.00%)까지
   여유가 있다"이다.
3. **합산이 개별 이익을 가린다.** 09-18에 NC가 +0.97%인데 NH투자증권이 -1.19%라 합산
   -0.19%로 묶여 둘 다 정리됐다. 09-16 산일전기 +2.17%도 합산에 가려 보유로 넘어갔다가
   -0.12%에 팔렸다.

## 결정된 것과 그 이유

**A. 익절을 제거한다.** `TAKE_PROFIT_PERCENT`는 2026-09-09에 자동 청산에서 빠진 뒤로 AI에
넘기는 참고 기준선으로만 남아 있었고, UI 입력란은 손절과 공유하고 있어 두 값이 항상 같았다
(그래서 둘 다 5%다). 매도를 일으키지 않으면서 설정·UI·프롬프트·메일 네 곳에 흔적만 남아
혼동을 만든다. 걷어낸다.

**B. 손절 판정과 매도를 종목별로 되돌린다.** 2026-08-10에 종목별에서 합산으로 바꾼 근거는
"규칙을 둘로 두면 먼저 팔린 종목의 확정 손실이 이후 합산에서 빠져 순서에 따라 결과가
달라진다"였다. A가 익절을 없애 **규칙이 손절 하나만 남으므로 이 근거가 해소된다.**

**①. 이익 반납 감시에 최소 고점 요건을 둔다.** 고점이 임계값 이상일 때만 감시 대상으로
삼는다. 새 설정 키는 만들지 않는다 — "1%p를 반납했다고 말하려면 최소 1%는 벌었어야 한다"는
뜻이라 같은 값을 쓰는 것이 자연스럽다.

**②. AI 프롬프트에서 손절선과 남은 거리를 뺀다.** 시스템 프롬프트는 이미 "손절선은 코드가
자동 처리하니 신경 쓰지 말라"고 못 박고 있는데도 AI가 그것을 주된 근거로 쓴다. user prompt가
`남은 거리 3.81%p`를 숫자로 주기 때문이다. **지시보다 데이터가 세다.** 주지 않으면 쓸 수 없다.

네 변경은 서로를 뒷받침한다 — A가 규칙을 손절 하나로 만들고, B가 그 손절을 종목별로 정밀하게
하고, ②가 손절선을 AI 시야에서 치워 되돌림 판단에 집중시키고, ①이 그 호출을 노이즈에서
건져낸다.

## 범위 밖

- **AI 매도 판단은 전량 매도를 유지한다.** AI에게 묻는 질문 자체가 "지금 전부 정리할
  상황인가"이고, 종목별로 바꾸면 프롬프트와 판단 구조를 함께 바꿔야 해 범위가 커진다.
- **`_execute_portfolio_exit` 경로를 새로 만들지 않는다.** 종목별 손절은 그 경로에 매도 대상
  목록을 좁혀 넘기는 형태다 — 주문·체결·알림·기록 로직을 재사용한다.
- **`AI_EXIT_DRAWDOWN_PERCENT`(1%p)와 `AI_EXIT_INTERVAL_MINUTES`(30분) 값 자체는 건드리지
  않는다.** ①은 임계값이 아니라 발동 조건을 고치는 것이다.
- **15:15 강제청산, 손절 on/off 토글, 일일 손실 한도, 총노출 비중은 그대로다.**

## 2. 손절을 종목별로 (B)

**판정** — `RiskManager.check_portfolio_exit`은 합산 순손익률 하나를 보고 `Optional[ExitReason]`을
돌려준다. 이를 **손절선에 닿은 종목 목록**을 돌려주는 형태로 바꾼다.

```
def check_position_exits(positions) -> List[str]
```

사유는 항상 `stop_loss` 하나뿐이므로 `ExitReason`을 함께 돌려주지 않는다 — 호출부가 안다.

- 종목별 순손익률은 기존 합산 계산과 같은 식(수수료·매도세금·슬리피지 차감)을 종목 단위로 쓴다.
- `stop_loss_enabled`가 꺼져 있으면 빈 목록. 계산 자체는 멈추지 않아 UI 표시는 그대로다.
- 합산 순손익률(`portfolio_return`)은 **UI 표시와 AI 프롬프트에 계속 쓰이므로 남긴다.**

**실행** — `TradingEngine._check_portfolio_exit`이 돌려받은 종목만 `_execute_portfolio_exit`에
넘긴다. 전량 매도 경로를 그대로 쓰되 대상 목록이 좁아진 것이다. `exit_reason`은 `stop_loss`로
동일하다.

**알림** — 기존에도 매도한 종목을 묶어 한 통으로 보낸다. 종목별로 발동해도 그 구조를 유지한다.

**되돌아온 대가**: 한 종목이 손절선에 닿아 팔린 뒤 나머지가 반등하면, 그 종목은 반등을 놓친다.
합산 방식에서는 다른 종목이 상쇄해 팔리지 않았을 상황이다. 이것이 2026-08-10에 합산으로 간
이유 중 하나였고, 이번에 의도적으로 되돌린다.

## 3. 반납 감시 최소 고점 요건 (①)

`DrawdownTracker.update`의 발동 조건에 한 줄을 더한다.

```
현재:  if peak <= 0: continue
변경:  if peak < self.threshold_ratio: continue
```

`threshold_ratio`가 0 이하면 감시를 끈 것으로 보는 기존 동작은 그대로다(그 분기가 앞에 있다).

**효과 검증** — 관측된 발동 11건 중 3건만 남는다.

| 종목 | 고점 | 현재 조건 | 변경 후 |
|---|---|---|---|
| 062040 | +2.17% | 발동 | 발동 |
| 005380 | +1.26% | 발동 | 발동 |
| 278470 | +1.02% | 발동 | 발동 |
| 000810 | +0.97% | 발동 | **제외** |
| 036570 | +0.49% | 발동 | **제외** |
| 005940 / 009540 | +0.35% | 발동 | **제외** |
| 267270 | +0.14% | 발동 | **제외** |
| 278470 | +0.05% | 발동 | **제외** |

`MAX_URGENT_TRIGGERS_PER_DAY`(10회) 상한은 그대로 둔다 — 발동이 줄면 상한에 닿을 일도 준다.

## 4. 프롬프트에서 손절선 제거 (②)

**user prompt** (`build_exit_user_prompt`) — `## 기준선` 섹션에서 손절선 줄과 남은 거리 계산을
지운다. 익절 기준선 줄은 A에서 이미 사라진다. 결과적으로 이 섹션에는 `현재 합산 순손익률`
한 줄만 남으므로, 섹션 제목을 없애고 그 줄을 `## 시간` 다음에 둔다. `stop_loss_ratio` 인자도
더 이상 필요 없다.

**system prompt** (`build_exit_system_prompt`) — `## 손절선과 익절 기준선` 절을 통째로 삭제한다.
주지 않는 정보에 대한 지침은 필요 없고, 남겨 두면 AI가 없는 숫자를 추측하게 만든다.

**남는 판단 재료**: 순손익률 궤적(시각별 합산/종목별), 종목별 되돌림(고점 → 현재, 반납폭),
아침 목표 매도가·근거·전망, 당일 공시, 15:15까지 남은 시간. 시스템 프롬프트의 판단 기준
1(되돌림)·2(아침 전망의 유효성)·3(장중 공시)은 그대로 유효하다.

**합산 당일 고점 줄은 남긴다** — 되돌림 판단의 재료이고 손절선과 무관하다.

## 받아들인 위험

- **이익 실현이 실제로 늘어날지는 돌려봐야 안다.** ①②는 AI가 일찍 파는 것을 늦춰 이익이 자랄
  시간을 주지만, 그 구간에서 AI가 이익 실현을 할지는 프롬프트 판단이라 보장할 수 없다.
  익절 자동 청산을 없앤 뒤로 **AI가 유일한 이익 실현 수단**이라는 구조는 그대로다.
- **①이 하방 대응을 늦춘다.** 고점이 작은 종목의 급락은 이제 즉시 트리거를 만들지 않고 다음
  정규 주기(30분)를 기다린다. 손절선에 닿으면 코드가 그 자리에서 처리하므로 최악은 손절선이다.
- **종목별 손절의 발동 빈도는 낮을 것이다.** 관측상 개별 종목이 -5%에 닿은 적이 없다. AI가
  먼저 파는 구조가 그대로면 B는 좀처럼 발동하지 않는다.
- **네 변경을 한 번에 넣으므로 무엇이 효과인지 분리되지 않는다.** 며칠 돌려 보고 되돌릴
  것이 생기면 항목 단위로 되돌릴 수 있게 커밋을 나눈다.
