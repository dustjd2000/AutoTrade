# AutoTrade

키움증권 REST API 기반 개인용 주식 자동매매 프로그램.

전략 로직을 갈아 끼울 수 있는 매매 엔진을 목표로, 인증·시세·주문·리스크관리·로깅 같은 공통 기반 위에
첫 번째 전략으로 **LLM 기반 급등 예상 대형주 매수 전략**을 얹었다.

상세 요구사항은 [주식자동매매_PRD.md](주식자동매매_PRD.md) 참고.

> ⚠️ 자동매매는 실제 손실로 이어질 수 있습니다. 반드시 모의투자(`TRADE_MODE=paper`)에서 충분히
> 검증한 뒤 실전으로 전환하고, 실전 초기에는 소액으로 시작하세요. 투자 책임은 사용자 본인에게 있습니다.

## 1호 전략 하루 흐름

| 시각 | 동작 |
|---|---|
| 08:40 | 일일 손실 한도·매매중지 상태 초기화, 총자산 기준 재산정 |
| 08:45 (UI에서 08:40~08:55 조정 가능) | 대형주 100종목 당일 데이터 수집 → LLM에 급등 예상 3종목 추천 요청 → 결과를 이메일 발송 |
| 09:00 | 예수금 × 1/2을 3등분(종목당 예수금의 1/6)하여 시장가 매수 → 매수 내역을 이메일 발송 |
| 장중 | 실시간 시세를 감시하며 **+2% 익절 / -2% 손절** 자동 청산 |
| 15:20 | 미청산 포지션 강제 정리 (당일 매도 원칙) |
| 15:30 | 당일 매매 결과 + 월간 누적 수익 리포트 이메일 발송 |

**보유 종목이 전부 매도되면 15:30을 기다리지 않고 결과 리포트를 보낸다.** 마지막 보유 종목이
팔린 뒤 체결이 잔고에 반영되면(약 1분) 리포트를 발송하고, **그 경우 15:30 리포트는 생략한다** —
익절/손절로 오전에 다 팔렸든 15:20 강제청산으로 정리됐든 같다. 리포트가 나간 뒤 다시 매수하면
표시가 초기화되어, 그 보유분을 또 전량 매도하면 다시 발송하고 남으면 15:30이 보낸다.
매도할 수 없어 보유 목록에서 제외된 종목(상장폐지·거래정지)은 이 판단에 넣지 않는다.

**시작 시 계좌에 남아 있는 종목은 그날의 매도 대상으로 편입한다.** 전일 청산에 실패했거나 앱이
꺼진 사이 넘어온 포지션을 찾아 실시간 시세를 구독하고(익절/손절 감시의 전제), 15:20 강제청산
대상에 포함시킨다. 편입 사실은 로그와 이메일로 알린다. 평단가는 최초 매수 시점 기준이므로,
이미 손절선을 넘긴 이월 포지션은 첫 시세가 들어오는 순간 청산된다.

**앱을 여러 날 연속으로 켜두어도 된다.** 스케줄은 날짜가 바뀌면 다시 발동하고, 08:40 리셋이
일일 손실 한도를 매일 새로 세운다. 주말에는 모든 스케줄 작업을 건너뛴다 — 다만 **공휴일은
걸러내지 못한다**(휴장일 캘린더 미연동). 휴장일에는 추천 메일이 나가고 매수는 거래소에서 거부된다.

## 구조

```
config/settings.py        환경변수 기반 설정 (모의/실전 분기)
src/api/                  키움 REST API 래퍼 (인증·시세·주문·잔고·WebSocket)
src/strategy/             교체 가능한 전략 모듈 (BaseStrategy 인터페이스)
src/risk/manager.py       리스크 관리 (익절/손절·일일손실·노출한도)
src/scheduler/            시간 기반 스케줄러 (08:40 / 추천 시각 / 09:00 / 15:20 / 15:30)
src/core/                 매매 엔진 및 하루 흐름 오케스트레이션
src/llm/                  LLM 추천 모듈 (Anthropic Claude API)
src/data/                 대형주 유니버스 및 당일 데이터 수집
src/logger/logger.py      날짜별 파일 로그 설정 (logs/autotrade/, logs/error/)
src/logger/trade_store.py 체결 내역 SQLite 저장 및 손익 집계
src/notification/         이메일 발송 (추천 결과·매수 내역·성과 리포트·운영 알림)
src/core/runtime.py       매매 런타임 조립 및 구동 (UI 스레드가 사용)
src/ui/                   PyQt6 UI — 설정 및 엔진 시작/정지 제어
```

## 시작하기

```bash
pip install -r requirements.txt
cp .env.example .env      # 값을 채운다 (.env는 커밋되지 않음)

python scripts/run_ui.py  # 유일한 진입점 — 설정과 엔진 제어를 모두 담당
pytest                    # 테스트
```

**엔진은 UI로만 제어한다.** 매매 엔진은 UI가 띄우는 별도 스레드에서 돌며,
UI의 시작/정지 버튼으로만 켜고 끈다. 창을 닫으면 엔진도 함께 정지한다.
(단독 실행용 `scripts/run_trading.py`는 제거했다.)

**설정을 저장하면 실행 중인 엔진이 자동으로 재시작된다.** 엔진은 시작 시점에 읽은 설정을 그대로
들고 돌기 때문에, 저장만으로는 스케줄 시각이나 익절/손절 라인이 바뀌지 않는다. 값이 실제로 바뀐
경우에만 재시작하고, 저장 완료 팝업("설정이 저장되었습니다. (재시작됨)")을 닫은 뒤에 재시작이
시작된다. **보유 종목이 있으면 먼저 확인을 받는다** — 재시작하는 동안에는 익절/손절 감시가 잠시
멈추기 때문이다(재시작 후 보유 종목은 자동으로 감시 대상에 다시 편입된다).

**"매도 불가" 표는 오늘 매도하지 못한 종목을 사유와 함께 보여준다.** 해당 건이 없으면 표가
숨겨진다. 매도 주문 거부(CB 발동 등)나 매도가능수량 0은 다음 청산 시각에 다시 시도되지만,
**상장폐지·거래정지로 보유 목록에서 제외된 종목은 자동 청산되지 않는다** — 계좌에는 남아 있고
보유 종목 표에서는 사라지므로 이 표로만 확인할 수 있다(붉은색 표기).

### 즉시 실행 (시간 무시)

스케줄 시각을 기다리지 않고 하루 흐름의 각 단계를 지금 바로 돌려볼 수 있다.
엔진이 실행 중일 때만 활성화되며, 스케줄러가 호출하는 것과 **동일한** 함수를 실행한다.

| 버튼 | 실행 내용 | 대응 스케줄 |
|---|---|---|
| ① LLM 추천 + 메일 발송 | 데이터 수집 → LLM 추천 → 추천 메일 | 추천 시각 (기본 08:45) |
| ② 매수 실행 | 예수금 배분 → 시장가 매수 → 매수 내역 메일 | 09:00 |
| ③ 전량 매도 (청산) | 보유 포지션 전량 시장가 청산 | 15:20 |
| ④ 최종 리포트 메일 | 당일 결과 + 월간 누적 리포트 메일 | 15:30 |
| 매수 및 매도설정까지 일괄 수행 | ①→② 연속 실행 (진입까지) | — |

- **"매도설정"은 별도 단계가 아니다.** 익절/손절 라인은 엔진 시작 시 이미 적용되어 있고, 매수로
  포지션이 생기는 순간 실시간 감시가 자동으로 붙는다. 버튼 이름은 실행 단계가 아니라 결과 상태를
  가리킨다. 지정가 매도 주문이 증권사에 미리 걸리는 것이 **아니라**, 설정된 비율(익절 %/손절 %)에
  시세가 닿는 순간 프로그램이 시장가로 청산한다 — 엔진이 켜져 있는 동안에만 동작한다.
- **익절/손절 판정은 가격 변동률이 아니라 순손익률 기준이다.** 매매수수료(매수·매도)·매도세금·
  시장가 슬리피지(`COMMISSION_PERCENT`/`TAX_PERCENT`/`SLIPPAGE_PERCENT`, `.env`)를 뺀 실수령
  기준으로 목표 비율에 도달했는지 본다. 그래서 손절은 가격 변동률상 -2%보다 조금 더 얕은
  지점에서, 익절은 +2%보다 조금 더 먼 지점에서 발동한다.
- **일괄 수행은 진입(①②)까지만 한다.** 청산(③)을 이어 붙이면 매수 직후 곧바로 되팔아
  익절/손절 감시 구간이 통째로 사라지고 왕복 수수료·슬리피지만 남는다. 당일 매도 원칙은
  15:20 강제청산 스케줄이 지킨다. 지금 당장 정리해야 하면 ③ 버튼으로 따로 실행한다.
- **리포트도 포함하지 않는다.** 당일 매매가 끝난 뒤에야 의미가 있는 집계이므로 15:30 스케줄에
  맡긴다 (엔진이 그 시각까지 실행 중이어야 발송된다). 지금 당장 필요하면 ④ 버튼으로 따로 보낸다.
- **④ 버튼은 최종 리포트를 대체하지 않는다.** 점검용으로 언제든 보낼 수 있고 발송 표시를 남기지
  않으므로, 전량 매도 리포트나 15:30 리포트는 예정대로 따로 나간다.
- **③ 전량 매도는 확인 즉시 시장가로 전량 청산한다.** 손익·보유 시간·익절/손절 목표를 보지 않는
  비상·점검용 버튼이며, 15:20 강제청산과 동일한 함수를 호출한다.
- 주문이 나가는 ②·③·전체는 실행 전 확인창을 띄우며, 실전 모드면 경고를 함께 표시한다.
- **장 시간 외에는 주문이 거래소에서 거부된다.** ①·④(메일)는 시간과 무관하게 동작한다.
- **매수·청산**은 엔진 이벤트 루프 스레드에서 실행되어 실시간 익절/손절 감시와 직렬화된다
  (같은 종목을 동시에 청산하는 경쟁 상태가 생기지 않는다).
- **수집·LLM·메일**은 30초 이상 걸려 루프를 막으면 WebSocket이 PING에 응답하지 못해
  서버가 연결을 끊으므로 별도 스레드에서 실행한다. 추천 시각 / 15:30 스케줄 작업도 동일하다.
- 진행 중에는 버튼이 잠기고, 정지 요청은 실행이 끝난 뒤(최대 60초 대기) 처리된다.

## 로그

```
logs/autotrade/2026-07-28.log   전체 로그 (날짜별 파일)
logs/error/2026-07-28.log       ERROR 이상만 — 문제가 생겼을 때 여기부터 본다
```

날짜가 파일명이라 지난 로그를 바로 고를 수 있고, 40일이 지난 파일은 자동으로 삭제된다
(`DEFAULT_RETENTION_DAYS`). 자정을 넘겨 실행 중이면 다음 날 파일로 자동 전환된다.

### 필요한 것

- 키움증권 계좌 + Open API 사용신청 → 앱키/시크릿
- Anthropic API 키 (LLM 추천용)
- Gmail 앱 비밀번호 (16자, 2단계 인증 필요) — 계정 비밀번호로는 SMTP 인증이 되지 않는다
